二：递归锁介绍

先讲一下什么是死锁？

日常生活的死锁：我们只招有工作经验的人！我没有工作经验怎么办？那你就去找工作啊！

程序中的常规死锁：

假设有2个互斥量M1、M2，2个任务A、B：

  • A获得了互斥量M1

  • B获得了互斥量M2

  • A还要获得互斥量M2才能运行，结果A阻塞

  • B还要获得互斥量M1才能运行，结果B阻塞

  • A、B都阻塞，再无法释放它们持有的互斥量死锁发生  

实际上，同一个任务也可以死锁：自我死锁。

看看这段代码：

xLock = xSemaphoreCreateMutex( );

void taskA(void *params)
{
    xSemaphoreTake(xLock, portMAX_DELAY);
    xSemaphoreTake(xLock, portMAX_DELAY);  //自我死锁
}

第1次成功的获得了互斥量，同一个任务，再次去获得同一个互斥量，会发生什么事情？

第2次获取互斥量时：失败，阻塞。

那谁能把他唤醒？互斥量的持有者，也就是它自己。

但是，他已经阻塞了，他无法再次运行，它不能够运行，就不能够去释放互斥量，所以将会永远的阻塞。

一般情况下，我们当然不会这么写代码。

但是，你要去调用某个库函数，这个库函数的代码你根本就看不到，没有办法修改。

xLock = xSemaphoreCreateMutex( );

void taskA(void *params)
{
    xSemaphoreTake(xLock, portMAX_DELAY);
    某个库函数();
}

某个库函数()
{
    xSemaphoreTake(xLock, portMAX_DELAY);
}

你要先去获得这个互斥量，才可以去调用这个库函数，库函数里面又会去获得同一个互斥量。

这时候发生：自我死锁。

因此，得想办法解决：

一个锁，任务A获得后：

  • 任务A再次去Take它，成功

  • 任务B有想去Take它，失败

如果能够实现上述功能，不就已经解决这问题了吗？

怎么实现这点？

  • Take成功时，记录持有者

  • 再次Take时，比较当前任务是不是持有者


有人再次去Take互斥量，会比较一下。

如果当前执行Take操作的任务，就是持有者本人，那么直接返回成功。

如果当前执行Take操作的任务，不是持有者本人，那么阻塞。

这就是递归锁。

1.什么叫做任务？

我们并没有非常严格的、学院式的定义，我们就看看怎么去保存一个运行着的程序：

假设程序运行时，暂停了时间，我们怎么去保存一个单片机里面运行的程序？

1.代码本来就保存在flash上，所以代码无需保存

2.局部变量保存在栈里，我只要不去破坏这块内存，栈无需保存

3.在运行过程中，各种中间值保存在CPU的寄存器里，这些寄存器需要保存下来

保存在哪里？怎么保存在内存里，为了方便：我们保存在这个程序的栈里。

有一些操作系统，他并不是把这些寄存器保存在栈里，它可以保存在tcb里。

4.把这个寄存器保存在栈里，栈的地址是什么？在TCB里记录下来

所以我们现在可以比较粗放的来定义什么是任务了：

1.一个运行起来的函数

2.有自己的栈

3.我们可以暂停它：暂停它的时候，需要保存它的运行现场，就是那些寄存器的值

4.我们可以重新让它运行：这时候就要去恢复他的运行现场，就是恢复之前保存的那些寄存器的值

如果要抬杠的，我可以用纯汇编来写出一个任务，它并不需要栈

但是一定得有：保存那些寄存器的地方，我们一般来说是在栈里面保存的，也可以在TCB里保存

3.我们创建出了任务，怎么调度呢？

1.抢占：高优先级的就绪任务，可以抢占低优先级的任务

2.轮转：相同优先级的就绪任务，轮流执行

3.空闲任务让步：他的每一次循环，都会主动去触发调度，让同是0优先级的任务优先执行


讲到调度我们就要涉及到任务的状态

有哪些状态？就绪、运行、阻塞、暂停

有这4类状态，会用3类链表来管理

就绪、运行，这两个任务都用readylist来管理：每一种优先级，都有一个ready list

有了这些链表，我们就可以知道怎么调度了


1.抢占：怎么体现？调度的时候，他怎么去选择出任务？

从ready list[31]开始查，依次ready list[30]……ready list[0]

从高到底开始查， readlist[30]是最高优先级， 通过配置设置优先级级数， 最大值31

因此，优先级的的数量有限，但任务的数量没有限制


2.轮转：链表中怎么体现?

每次取出readylist[x]的第一个任务执行，该轮转时这个任务就从头部取出放回队尾

问：老师，任务中加入vTaskDelay(1);假如没有其他任务在执行。是不是这个任务相当于每1ms执行一次循环？

问：链表对插入任务是有优先级排序的吧？

答：在ready list中，插到优先级对应的ready list[优先级]在queue的list中，会根据优先级排序


问：老师，cpu从readylist取出任务后，是立即把此任务放到readylist尾部吗？

还是任务运行完后再根据情况放到readylist还是其他list？？

答： 从头部取出来运行 ，然后放到尾部。实际上内部实现稍有差别


问：老师，队列也是全局变量吧？

答：我们使用xQueueCreate来动态创建队列，它的handle我们经常写为全局变量，

但是队列本身是动态分配出来的，不应该认为是全局变量

信号量时全局变量吗？它是动态分配出来的，不属于全局变量

它的handle，你可以设置为全局变量，指向动态分配出来的结构体

我们可以更灵活一点：

1.FreeRTOS中定义了一个巨大的全局数组，它在bss段里

2.FreeRTOS实现了malloc、free函数在管理这个全局数组，所以这个全局数组是堆

3.我们malloc一块内存后，可以把它用作任务的栈
