前情提要

上节课我们讲了什么是任务，讲了当一个任务被打断时如何保存它的现场，最后我们表示一个任务的时候，构造出来了一个结构体：

struct Task{
    // 函数指针
    // 栈
};

结果我们看到FreeRTOS的代码中，任务结构体中并没有函数指针这样一个成员：

struct Task{
    // 栈
};

可以看到其中最核心的东西就是栈，可为什么这个任务结构体没有函数指针呢？这样定义的一个任务被打断的时候不需要保存里面的函数指针吗？其实已经保存下来了，就是保存在栈里面的。栈保存有寄存器的值，其中PC寄存器的值就是程序执行到的地址，我们让栈保存了寄存器PC的值，也就是保存了函数的地址。

什么是栈？栈其实就是一块内存，可以由malloc动态分配内存，也可以自己定义一个数组让栈有一个静态的内存。

BaseType_t xTaskCreate( TaskFunction_t pxTaskCode,

第二个参数：pcName并不重要，只是表示任务的名称；我们的任务函数，他有一个参数

void *param

这个参数由谁传递给任务函数？在外面创建任务的时候就可以传入一个参数，也就是创建任务的函数的第四个参数：

void * const pvParameters

当我们的任务函数运行起来的时候，创建任务时传入的这个参数就会被利用起来。

创建任务的函数的这几个参数中只剩下最后一个优先级参数：

UBaseType_t uxPriority

以我们在讲解RTOS课程的最开始举的例子：一个妈妈要做几件事：喂饭、工作和救火。这几件事情中，哪件事最紧急？那肯定是救火最要紧，那么救火这个任务的优先级更高，需要先去做。我们创建任务的时候也是一样的，要替CPU考虑这些任务谁更紧急，谁先处理谁后处理，也就是给这些任务分配优先级。

1.2 创建静态任务

我们刚才一直学习的都是创建动态任务的函数，我们当然也可以创建一个静态任务，来看一下它的函数原型：

TaskHandle_t xTaskCreateStatic( TaskFunction_t pxTaskCode,
                                    const char * const pcName,
                                    const uint32_t ulStackDepth,
                                    void * const pvParameters,
                                    UBaseType_t uxPriority,
                                    StackType_t * const puxStackBuffer,
                                    StaticTask_t * const pxTaskBuffer )

其静态分配的栈和任务结构体就是依靠最后两个参数完成的。

  • 对于栈，我们可以事先定义一个数组；

  • 对于任务结构体，我们可以事先定义一个全局变量；

其它的参数和创建静态任务的函数xTaskCreate完全一样。

二：RTOS中的变量

我们首先应该清除一个变量的作用域：

2.1 全局变量

我们不要以为任务函数就是一个拥有特殊作用的函数，其实它和一般的函数是一样的。一般的函数可以访问全局变量，任务函数当然也可以。但是在RTOS中，这样会有一个问题：

  • 任务1使用全局变量a，任务2也会使用这个全局变量a；

你用我也用，你写我也写，如果是轮流写的话还没什么问题，但是如果是交叉写的话，就会出问题了。我们来举一个例子：

int g_a;
int add()
{
    g_a++;
}

我们假设有两个任务都会去调用这个add函数：

void Task_1(void *param)
{
    add();
}

void Task_2(void *param)
{
    add();
}

从代码上看，add函数只有一条指令，但是从汇编上看它实际由3条指令需要执行：

  • 都内存；

  • 加1；

  • 写回去；

在这几个步骤中，都有被打断执行的可能，那么对比顺序执行或者说轮流执行任务得到的结果就完全不同了：

任务1和任务2都去执行了加1操作，理想的结果是全局变量最后等于2，但是如果有一个任务被打断了按照左侧的方式执行，那么最后全局变量的值却是1。有经验的同学就知道，这种情况下需要互斥操作，我们这里并不是打算去讲互斥操作，会在后面讲它。这里只是告诉大家，任务函数跟普通任务没有差别，它同样可以去访问全局变量，只不过对于多任务访问同一个全局变量的话，结果可能就不会是你预期的那个结果。

为什么FreeRTOS的任务不能够直接返回呢？对于这个问题，我们先要思考下面这几个问题：

  1. 任务函数返回的话，返回到哪里去？

    我们创建这个任务的时候，运行这个任务的时候，我们有设置过它的返回地址吗？在FreeRTOS中是没有设置的，但是在RT-Thread就有设置，所以对于FreeRTOS的任务而言，是不能够直接使用return返回的。

  2. 如果不想永远循环这个任务该怎么做？

    使用break退出任务中的while(1)可以吗？显然是不可以的，退出while(1)之后也是返回，那怎么做？自杀或者被杀！

所谓自杀，就是向系统声明：我不参与调度了，用别的任务替换我吧，我永远都不参与调度了。

五：自由问答

问：RT-Thread是如何退出任务、删除任务不参与调度的？

答：RT-Thread可以直接返回，因为他设置了返回地址：你返回的话，系统会帮你自杀。


问：任务之间可以随便互杀还是有什么规则？

答：FreeRTOS没有权限管理，可以随意互相删除。全靠程序员自己管理了，删除之后想用还得重新创建。


问：既然可以杀别的任务，任务可以创建任务吗？

答：可以。


问：低优先级任务可以杀高优级任务吗。

答：可以。


问：我们创建任务时怎么确定栈的大小？

答：这个取决于你的局部变量还有函数的调用深度。


问：函数深层嵌套是不是容易崩溃。

答：关键在于嵌套有没有退出：递归调用，只要退出机制做得好，不要无穷地递归，是没问题的。


问：事先分配好和动态分配有啥区别呢，存储位置不一样吗？事先分配好放在bss，动态分配在堆区？

答：这句话这样说基本没错，对于freeRTOS它就有点特别。freeRTOS是定了一个很大的数组，malloc是从这个数组里分配空间。所以：堆在数组里，堆在BSS里。


问：什么叫做堆？

答：是一段被管理起来的内存 ，可以从里面划分出一块来使用。我定义了一个全局数组，我想去使用内存时，用这个数组里面的内存，可不可以？当然是可以的。


问：源码里定义了一个很大的数组，这个数组多大有规定吗？

答：没有规定，不要超出你的内存范围就可以。


问：全局变量和静态变量保存在数据段或者BSS段吧？

答：有初始值的全局变量、静态变量，保存在data段；没有初始值的全局变量、静态变量，保存在BSS段。


问：请问堆的定义不是一块空闲的内存吗，如果在data段定义一个数组来用，那么需要堆干嘛呢，是freertos的特别用处吗？

答：1. 堆的定义：被管理的一块空闲内存，可以实现malloc、free函数，从这块内存里分配、释放内存；

2. 我可以用一个数组来占坑，霸占一块空闲内存，然后实现malloc、free，所以定义了数组之后，还需要堆干嘛呢？这个堆，就是这个数组，我需要这个数组占坑；

3. FreeRTOS使用数组来占坑，是一个很妙的主意，这个数组太大了，编译器会帮你报错。


问：任务创建  、任务函数和任务控制块， 联系和区别。

答：创建一个任务：我们需要分配一个结构体来表示这个任务，这个结构体就是任务控制块；一个任务，总得做些什么事情吧？这就是一个函数；


问：freertos在数据段利用数组占空间，他自己也实现了malloc或free函数吗？

答：实现了。
