一：上节回顾

事件组就是一个整数：每一位用来表示一种事件。

生产者：去设置事件，

消费者：去等待事件

跟信号量的差别在于：我们可以等待一个或者多个事件

等待到事件之后，可以清除掉事件


使用信号量呢，等待一个信号量，并不能够等待多个事情

实际上事件组跟队列集反而有些类似：使用队列集的时候，我们可以去等待多个队列

但是使用对队列集主要是为了传输数据

如果并不需要传递数据，只是为了有个提醒作用，用信号量

提醒一件事：用信号量

提醒一件事或者多件事：使用事件组


二：事件组的使用

2.1一般使用

一般的使用，举个场景：

  • 任务3等待事件0与事件1：xEventGroupWaitBits

  • 任务4等待事件0或事件1：xEventGroupWaitBits

  • 任务1产生事件0：xEventGroupSetBits

  • 任务2产生事件1：xEventGroupSetBits

  • xEventGroupSetBits函数里判断任务能否被唤醒

    • 别人是谁？

    • 就是等待事件的任务

    • 它调用xEventGroupWaitBits时，可以声明是否要清除某些位

    • 会判断所有的任务

    • xEventGroupSetBits唤醒任务后，退出前，可以应别人的要求清除事件

2.2同步点

用事件组是我们即将讲的方法，我们说如果没有事件组的话，我们能不能够实现这个目标

用信号量，ABC都要吃饭，A等到信号量后，BC就得不到同一个信号量

无论你是使用队列、信号量，ABC都在等待，并且只会有一个人得到，所以不太适合

如果非要用队列、信号量，那就引入第4个任务

A做完信号量+1休眠，B做完信号量+1休眠，C做完信号量+1休眠，D判断信号量==3，把ABC放入readylist


假如用事件组呢？

A：设置bit0，等待bit0,1,2，不清除

B：设置bit1，等待bit0,1,2，不清除

C：设置bit2，等待bit0,1,2，不清除

这样，ABC都完成自己的事，就可以等待别人，别也都完成了，就可以开饭


这样办法是可行的，但是对于下一次循环，就有点麻烦：谁来清除这些事情？

所以我们要引入事件组的同步点

我们来假设：

1.任务A调用xEventGroupSync，他设置了bit 0，想等待bit0,1,2， 于是阻塞

2.任务B调用xEventGroupSync，他设置了bit 1，想等待bit0,1,2， 于是阻塞

3.任务C调用xEventGroupSync，他设置了bit 2，想等待bit0,1,2，


在这个函数内部：

3.1 把任务A，任务B唤醒

3.2 问题来了

在红色箭头那个函数内部，他会唤醒任务A, 会把任务A期待的bit0,bit1,bit2清零吗？

注意：任务A调用xEventGroupSync而阻塞，并没有调用xEventGroupWaitBits（也就是说没有要求清除）


我们现在重新走一遍代码

1.任务A调用xEventGroupSync，他设置了bit 0，想等待bit0,1,2

调用xEventGroupSync，如果条件不成立，就相当于调用xEventGroupWaitBits


2.任务B调用xEventGroupSync，他设置了bit 1，想等待bit0,1,2

调用xEventGroupSync，如果条件不成立，就相当于调用xEventGroupWaitBits

现在，应有任务A、任务B都在等待这个事件组


3.任务C调用xEventGroupSync，他设置了bit 2，想等待bit0,1,2

所以：

任务A调用xEventGroupSync成功

任务B调用xEventGroupSync成功

任务C调用xEventGroupSync成功


最重要的一点在于:

在这同一时刻，大家都等到了自己的事件，都处于就绪态，同步了

这就是同步点这个名字的由来。

三. 晚课学员提问

问：如果有3个任务在等待事件，有一个任务要清除事件，其他两个任务会受事件被清除的影响吗

答：假设：

1.任务1等待 bit0

2.任务2等待 bit 0 与 bit1

3.任务3等待 bit 0 或 bit1

下载任务4设置了bit0，会发生什么事？


会唤醒任务1和3，分析一下这个过程

首先这三个任务都在等待事件组，

然后task4调用xEventGroupSetBits设置了bit0

在这个函数xEventGroupSetBits里面：

1.他会判断所有等待这个事件组的任务，也就是说他会判断task1, task2, task3哪些任务符合条件了?

2.task1, task3被唤醒，并且把当前事件值记录在他们自己的TCB里。他会去链表里面从头到尾取出来一个一个判断，这些任务的优先级，他根本不在乎

3.最关键的一点来了：xEventGroupSetBits判断完所有的任务之后，会做什么事情?

3.1 如果task1被唤醒了，task1等待事件时表示说要“清除”：那么xEventGroupSetBits会清除掉bit0

3.2 task2没被唤醒，它想清除某些位：不用管它

3.3 task3被唤醒了，task3等待事件bit0或bit1，并表示说要“清除”：那么xEventGroupSetBits会清除掉哪一位？

task3虽然只等到了bit0，但是它等待的时bit0或bit1，于是会把这2位都清掉

问：老师，那您举例的这种程序， task2 是不是被触发的概率极小 bit0事件和bit1事件一发生就会被清掉？

答：如果bit0先发生，bit0马上就被清掉

问： 关中断和开中断的含义能在深入讲解下嘛？

答：还记得我们讲了这个例子吗

我们想用一个全局变量，来互斥地使用串口

他失败的原因在于：任务A读出全局变量后，被切换为任务B执行了

那如果：我在访问这个全局变量之前，直接关闭中断，不就可以避免别的任务来抢占了吗？

所以FreeRTOS就是通过关中断来互斥地、独占地访问队列、信号量、互斥量、事件组

这就是关中断的作用

实际上，对于更加先进的处理器，很多时候的并不需要关中断

比如说对于这个全局变量的修改，cortex A7

有一些汇编指令,去修改这个全局时，可以是原子性

所谓原子，就是不可分割，也就是他去修改这个全局变量时，没有人能够打断他


我们再来看看开中断

1.在关中断后，程序执行了很多代码，可能已经让某些高优先级的任务就绪了

2.所以在开中断之后，一般都会去调用一个调度函数


问：不仅仅是队列、信号量、互斥量、事件组，只要是访问全局变量的时候都要关闭任务调度，如果中断有对全局变量操作的话，中断也要关吧

答：低优先级的中断、高优先级的中断，都使用同一个全局变量的话

在低优先级的中断里，就要屏蔽高优先级的中断：他不能够被高优先级的中断所打断

在高优先级的中断里，并不需要去屏蔽中断：低优先级的中断本来就不能抢占我


问：如果是一个全局变量只被一个任务A赋值，任务B C只使用这个全局变量，不给它赋值，这样是否就能保证安全？ （如果不用rtos的传递全局变量的方法）

答：很安全


问：如果中断不会丢失的话，那根据中断的优先级在中断里处理和在中断里置位然后再根据任务优先级处理感觉没啥区别啊？

答：我们假设中断不会丢失

1.中断A来了，需要执行10ms

2.在处理A的过程中，来了中断B，中断B不会丢失，但是中断B无法立刻得到执行，必须等中断A执行完

如果用RTOS的话：

1.中断A来了，唤醒任务A

2.中断B来了，唤醒任务B

任务A、B同时执行，中断A、B都得到了快速的处理

再加上一个改进后的前后台系统：

1.中断A来了，设置flagA

2.中断B来了，设置flagB

3.main函数循环判断flagA，处理A，耗时10ms

main函数处理完A，再判断flagB，这时才能处理B，B的处理被A推迟了很久

所以，RTOS跟前后台的比较，关键在于：RTOS可以“同时”处理“多任务”

而不是：中断的丢失与否


问：老师，FreeRTOS的中断指的就是ticks中断吧？

答：FreeRTOS中的中断，根据优先级分为2类：

1．小于等于：configMAX_SYSCALL_INTERRUPT_PRIORITY

2．高于：configMAX_SYSCALL_INTERRUPT_PRIORITY

第1类中断中，可以调用FreeRTOS的API函数，可能会导致任务切换

我们说的“关中断”，就是关闭第1类中断

关闭这类中断后，再去执行FreeRTOS的函数就很安全：那些要跟你抢资料的中断都被禁止了
