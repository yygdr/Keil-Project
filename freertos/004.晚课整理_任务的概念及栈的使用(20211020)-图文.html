1.1 什么是任务？

我们先来举几个反例。

  • 任务是函数

这肯定是不对的，或者说不是完全准确的。如果说任务是函数，那么下面这段代码：

void Task1Function(void *param)
{
    while(1)
    {
        printf("1");
    }
}

这是一个任务吗？其实不能这么说，它是任务的一个函数，是任务的一部分，但不是任务。如果一个函数就等于任务的话，这个函数，保存在flash中，在我们切换任务的时候并不需要保存它(对于任务而言，我们是可以对它进行创建、删除、切换等操作的)；既然它都已经保存在Flash中了，我还创建或者删除它干什么呢？

所以函数是任务的一部分，不是任务的全部。

那么任务到底是什么呢？我们可以这样认为：任务就是一个运行着的函数。我们来看一段代码来理解这句话：

void add_val(int *pa, int *pb)
{
    volatile int tmp;
    tmp = *pa;
    *pa = tmp + *pb;
}

void TaskFunction(void *param)
{
    int a = 1;
    int b = 2;
    
    add_val(&a, &b);
}

我们来看看它是怎么运行的。在理解这段代码的运行机制之前，我们首先需要简单的了解一下ARM架构，所以我们这里先来简单讲一讲ARM架构。

1.2 简单认识ARM架构

int a = 1;

这两个变量必定在内存里，那么对于语句：

我们怎么执行这个计算？对于内存而言，只能读只能写，那谁来计算？是由CPU来完成计算的。

CPU把变量a和变量b从内存中读出来，完成a+b然后再将结果写入内存中，这个过程中又有几个问题需要我们去思考。

  • CPU从内存中把变量的值读取出来保存到CPU的哪里？

  • 运算完之后的结果又保存在CPU的哪里？

① CPU从内存把变量a的值读入CPU的R0寄存器；

1.3 简单汇编指令

这里又需要讲解几条汇编指令了。大家不要畏惧汇编指令，今晚我们要讲解的也只有3条汇编指令，日常中常用的汇编指令基本也只有七八条。先来看看今晚会用到的这三条汇编指令吧：

load  ; 加载
store ; 存储
add   ; 相加

load加载指令，传输数据三要素：源、目的、长度。

  • 源：从内存的何处加载？即需要一个地址；

  • 目的：加载的数据保存到何处？刚才说了是CPU的某个寄存器；

  • 长度：变量的长度，比如int a;这个变量的长度是4bytes(32bits的处理器)；

所以我们就可以得到一条加载指令的语句：

LDR R0, [地址]

store存储指令，写内存也需要三个要素：源、目的、长度。

  • 源：CPU的某个寄存器

  • 目的：内存地址；

  • 长度：变量的长度

同样可以得到一条存储指令的语句：

STR R0, [地址]

add加指令，这条指令很简单：

ADD R1, R2, R3 ; R1 = R2 + R3

① 调用一个函数时，参数是怎么传递的？

我们调用一个C函数，第一个参数会保存在CPU的R0寄存器，第二个参数会保存在R1寄存器：

R0 = &a = a在内存中的地址

② tmp = *pa

它有两条指令：

LDR r2, [r0, #0x00]
STR r2, [sp, #0x00]

我们来分析这两句代码。第一句，CPU从源为R0寄存器偏移0x00个单位后的地址的值读取出来保存到目的R2寄存器，也就是将a的值读取出来保存到R2寄存器；第二句，将源R2寄存器的值存储到目的地址为sp寄存器偏移0x00单位后的内存中。

③ *pa = tmp + *pb

它有4条指令：

LDR r2, [r1, #0x00]
LDR r2, [sp, #0x00] ; 前面sp偏移0x00单位后的地方保存的是a的值
ADD r2, r2, r3
STR r2, [r0, #0x00]

根据前面的经验，我们可以很容易的得到这段代码的过程就是，先将变量b的值读出来保存到R2寄存器，然后将a的值读出来保存到R3寄存器，之后执行相加指令，将R2和R3的值相加保存到R2寄存器，也就是将a的值和b的值相加之和的值保存到R2寄存器，最后将R2寄存器中的值即相加之后的值保存到R0寄存器偏移0x00之后的地址的内存中。

1.4 保存现场与恢复现场

  • 保存地址

    当程序运行到某个地方或者说某个地址忽然被打断，我们是需要将这个地址保存下来的，比如前面那张图的0x08001108，我们是需要将这个地址保存下来以便打断的任务完成后回到这里来继续运行后面未完成的动作的。

  • 保存寄存器

    我们需要将打断前的寄存器的值保存下来，同理也是为了让CPU完成打断的任务之后回到保存下来的那个地址继续执行未完成动作时知道被打断前的寄存器的值，只有这样才能在执行之后的动作后得到正确的结果。

  • 现场保存的位置

    CPU将打断前的程序运行到的地址、寄存器的值保存到栈中，当执行完打断后，又从栈中读取出来恢复现场继续执行。

1.5 栈的作用

前面的汇编代码中，我们只分析了add_val函数中的LDR、ADD和STR指令，但是一开始的

PUSH [r2, lr]

是在做什么呢？它有这三个过程：

PUSH，压栈，其实本质上也是STR写内存指令。大家可以看到，PUSH指令做了3件事情：

  • 把返回地址LR放入栈里(LR中保存的就是返回地址)；

  • 把R3寄存器中的值放入栈里；

  • SP = SP - 8;

问：为什么sp是减8？

答：因为往栈中写入了两个寄存器的值，在32bits中一个寄存器占32bits也就是4个字节，这里是两个寄存器，也就用了8个字节，因而是sp-8。

问：返回地址是多少？R3是干什么用的？

答：

BL.W是一条汇编指令：branch and link，译为跳转、保存返回地址。它保存的是下一条汇编指令的地址：

它要保存的就是prvSetupHardware这条汇编指令的地址：0x080011B6。

我们再来看看局部变量在栈里是怎么体现的。

前面的讲解其实已经解释了栈的作用：

  • 保存返回地址；

  • 保存局部变量

那么局部变量是怎么起作用的？

我们要保存R3？R3入栈是为了给局部变量占位。有时候为了给局部变量占位，汇编里面直接这样写：

SUB SP, SP, #4

入栈的寄存器R3、R4、R5还是其他都没关系，因为只是为了占个坑而已。

PUSH [r3, lr]

可以改为

PUSH [r3]
SUB SP, SP, #4  // SP = SP - 4, SUB是减法指令

我们在栈里占坑了，那局部变量到底是怎么体现的呢？

我们在栈中占了一个位置SP，将其视作局部变量tmp的地址，当读写局部变量时就是对栈地址的读写，所以说：局部变量保存在栈中。大家应该就理解这句话的意思了。

最后那句POP指令就是弹栈，之前保存的LR赋值给PC寄存器，然后恢复SP的原始值：SP=SP+8，这样就恢复了现场，回到进入add_val前的地址继续执行后面的指令。

我们说任务是一个运行的函数，它运行的时候需要：

  • 指令，也就是那些函数代码，那些函数代码需要我们自己去保存吗？不需要，只需要知道它运行到了哪里就可以；

  • 栈，用来保存各种寄存器、各种局部变量；

如果打断了运行中的函数，栈需要保存吗？栈的内容需要保存吗？寄存器要保存吗？

栈的内容不需要保存，只需要保存栈的位置。栈本身就是一段内存，你把一段内存保存到哪里？把一段内存保存到另一段内存里面去？所以栈里面的内容不需要保存，只要别人不破坏它就可以。如果不保存栈的位置，下次这个函数重新运行的时候，CPU怎么知道从哪里找到之前保存的那些寄存器和局部变量。寄存器的值是需要保存的，它们还是保存到栈里的。

我们来举个例子理解：

函数的调用关系是：A——>B——>C：

  • 函数A会调整栈：SP=SP-Len_A;

  • 函数B会调整栈：SP=SP-Len_B;

  • 函数C会调整栈：SP=SP-Len_C;

假设是在函数C的内部被打断了，我们要保存那些东西？

  • 指令位置：指定到函数C的哪里；

  • 栈的位置：SP，就是SP=SP-Len_A - Len_B - Len_C；

  • 寄存器的值；

所以你调用再多的函数都没关系，我并不需要去保存每个函数的栈的位置，我只需要保存备切换的时候的栈的位置即可。每个函数都有自己的栈，或者说每个函数在运行的时候都有自己的栈空间，注意，是运行时，局部变量越多，栈就占的越大；函数调用的深度越深，栈也占的越大。

问：每个任务中函数用到的栈内存都是连续的，但是不同的任务之间的栈内存不是连续的。

答：

任务1： 函数A->B->C ,任务1的栈内存是连续的； 任务2： 函数E->F->G， 任务2的栈内存是连续的； 任务1、任务2的栈内存，不能重合；

问：每个函数对应的栈如何划分出来，是不是以lr入栈出栈做分隔呢？

答：不需要我们自己去划分，函数进去时会自动计算占用的栈空间，退出时又会释放这些空间。

问：我定义了四个局部变量，编译器只给我分配了我要用的两个，编译器是怎么在之前就知道的呢？

答：编译器发现函数没有用到这些变量在编译的时候就不会给他们分配内存。

二：任务的表示

一个任务有：

  • 函数；

  • 地址：运行到何处；

  • 栈；

  • 寄存器的值；

其中地址和寄存器的值都可以保存到栈里，所以我们就可以这样来表示一个任务：

struct Task{
    // 函数指针
    // 栈的位置
};

  • 栈里保存有：函数的地址、寄存器的值等；

  • 每个任务都有自己的栈，如果任务1、任务2使用相同的栈，任务1的局部变量就会被任务2给破坏掉；

三：自由问答

问：SP记录的是切换到某个任务的启始运行的地址？PC 是运行的位置？

答：SP记录的是任务的当前栈位置，PC记录的是任务当前的运行位置。

问：函数指针指向了某个函数的地址吗？

答：函数指针这个变量，保存的本来就是函数的地址

问：是不是在一个函数的运行过程中只有开始和结束时会改变sp的值（不考虑调用其他函数，或被打断）

答：是的

问：任务的栈位置记录在哪里呢？

答：创建任务时会有一个结构体，结构体里面会有一个成员，这个成员用来保存栈的位置。

问：保存当前任务某个运行的地址，这个是硬件自动操作的吗？什么样触发这个操作。

答：要切换程序的时候，有软件来做的，不是硬件触发。
